# 自主 Qwen 与原生 C 计算器

[English](autonomous-calc.md) | **简体中文** · [返回首页](../../README.zh-CN.md) · [验证索引](../../VALIDATION.zh-CN.md)

实现提交 `15a00d4` 将原生 C 计算器接入由 GPU 控制的条件 CUDA 执行图。
使用 **Qwen3.5-4B-Qwenputer BF16，关闭 thinking**，三个真实模型用例均返回精确答案并正常 EOS。
完整文字 token 流和反馈标记与主机对照一致；主机对照每个 token 启动一次**相同的已捕获步骤**。

| 用例 | 调用次数 | CPU 逐步控制耗时（秒） | GPU 控制耗时（秒） | CPU 逐步启动次数 | GPU 主机启动次数 |
| --- | --- | --- | --- | --- | --- |
| `2*8` | 1 | 1.925 | 1.924 | 66 | 1 |
| `12345678901234567890*98765432109876543210` | 1 | 5.939 | 5.943 | 210 | 1 |
| `123456789*987654321`，再对返回结果加上 `12345` | 2 | 6.833 | 6.843 | 241 | 1 |

存在依赖的用例实际生成了两次独立调用，分别为 `123456789*987654321` 和
`121932631112635269+12345`，得到 `121932631112647614`。
第二次调用使用了第一次工具返回的整数。三个用例的两组运行均在原版 CPU 参考固件上独立重放，
所有由工具生成的反馈 token 均一致。最终状态还通过了精确答案、顺序、源码哈希、
缓存位置和 token 计数检查。

GPU 工具区间包含门控、RAM 恢复、虚拟机执行和反馈编码：`2*8` 为 0.294 ms，
40 位十进制数乘积为 0.804 ms，两次有依赖的调用分别为 0.517/0.467 ms。
参数收集和模型前向计算位于该区间之外。语言生成占据这些 batch 1 请求的主要耗时。
**在这个小样本中，相对于使用相同已捕获步骤的主机对照，没有明显的耗时改善**。
这些是单次测量，不是统计意义上的加速研究，也不是对此前 200 题评测的重跑。

对有依赖请求进行整图级 Nsight 采样，记录到**一次主机 `cudaGraphLaunch` 和一次最终
`cudaStreamSynchronize`**，请求期间**没有主机 kernel 启动或 memcpy API 调用**。
最终轨迹包含两次成功的计算器调用和 239 次解码前向。
整图跟踪不显示各个内部 kernel 或拷贝节点，因此不能根据报告推断这些节点不存在。
所测执行图包含真实提示词预填充；初始模型加载、分词、捕获、初始化、缓存重置，
以及最终轨迹下载和参考检查仍由 CPU 在请求区间外完成。

已测试的范围为固定 C 计算器、batch 1、静态缓存和执行图形状，以及有预算限制的生成。
这并未证明 GPU 可控制任意 MicroPython 路由、27B 兼容性、推理服务并发或吞吐量。
Nsight 2025.1.3 的节点级跟踪加自动事件跟踪触发了非法内存访问；
文档中的整图级跟踪并关闭事件跟踪的配置正确完成。采样时的总耗时未计入上表。
全部 **73 项回归测试**通过；wheel 和源码包构建，以及随包控制器资源检查也已通过。
