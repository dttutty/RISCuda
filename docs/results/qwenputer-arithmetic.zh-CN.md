# 对齐的 200 题 Qwenputer 算术评测

[English](qwenputer-arithmetic.md) | **简体中文** · [返回首页](../../README.zh-CN.md) · [验证索引](../../VALIDATION.zh-CN.md)

按照原作者公开的五组题、随机种子 0、每组 40 题的设置，
两种实现均答对 **195/200（97.5%）**。在**两组答案精确且正常 EOS 的 194 对请求**上，
RISCuda 总请求耗时降低 **15.92%**（Qwenputer/RISCuda 耗时比为 1.1893；
按配对题目进行 2000 次重采样 bootstrap，耗时降低比例的 95% 区间为 **14.15%–17.68%**）。

| 数据集 | 每组精确答案数 | 双方正确且正常 EOS 的配对数 | RISCuda 平均秒数 | Qwenputer 平均秒数 | 耗时降低 |
| --- | --- | --- | --- | --- | --- |
| 合成 `arith` | 39/40 | 39 | 9.15 | 10.14 | 9.81% |
| DeepMind `mul_big` | 39/40 | 39 | 6.49 | 7.37 | 11.91% |
| DeepMind `div_big` | 39/40 | 38 | 7.17 | 8.62 | 16.83% |
| DeepMind `mul_div_multiple_longer` | 40/40 | 40 | 59.69 | 72.73 | 17.93% |
| DeepMind `add_or_sub_big` | 38/40 | 38 | 9.66 | 10.68 | 9.58% |

数据包含负数、小数和有理数答案。耗时列仅使用第三列所示的双方正确完成子集。
全部请求，包括失败和截断，都保留在数据中：RISCuda 累计耗时 **4589.96 s**，
Qwenputer 为 **5382.87 s**，降低 **14.73%**。这些数值是逐请求时长之和，
不是两个并行 GPU 作业的实际总运行时间。每组均有五次预算截断，其中一次在截断前
已给出正确的 boxed 答案。因此，精确答案准确率与正确完成请求数分别统计。

两组对齐了语言参数、BF16 精度、原版提示词预填充、提示词 ID、计算器协议、greedy 解码和关闭 thinking。
本地全部八个检查点分片及分词器和推理配置哈希均与 ModelScope 上的
`Spartan1925/Qwen3.5-4B-Qwenputer` 一致。缓存的原作者检查点版本为
`2d9068508f2b680badb7abcded96fdd107e9ba5d`。
RISCuda 执行相同的原作者 `calc.c`，使用 CUDA 十进制行绑定，保留原有限制和计算器语义。
标准答案未进入推理或工具执行。两组均保留 CPU token 循环。

两张已确认空闲的 RTX A6000 分别运行互不重叠的 100 题分片，每个配对使用同一张 GPU，
并交替两组的执行顺序。推理实现提交为 `f82e40bc3411e2092b27814b6be38272f3dbb35e`，
Qwenputer 上游提交为 `ca13310e2f9f788d1dd3feeea8213c1b0c23913c`。两个作业均以状态 0 退出。
计时包含提示词预填充、生成、计算器执行和反馈，不包含加载、编译、预热和独立 CPU 验证。
每个题目、每组各测量一次请求，batch 1。软件版本和完整命令记录在证据中。
共享的 Torch 2.9/CUDA 12.8 环境未安装可选的 causal-conv1d 和 FLA。

独立验证重新生成了选定题目，检查源码、ELF 和分片哈希，重新评分精确有理数答案，
并在原版 CPU 参考机上重放每个由固件生成的 token 和反馈。
**全部 400 次运行通过执行和轨迹验证。199/200 对**的完整文字 token 流一致，
**200/200 对**的共同前缀均一致。唯一长度不同的用例是 `div_big-4617`：
Qwenputer 在 3513 个文字 token 时达到 200000 个芯片 token 上限，
RISCuda 则继续到 4096 个文字 token 上限。两组答案均错误或截断；
此配对不计入主要耗时对比。每次实际原生计算器调用的 RISCuda 虚拟机执行状态和客户机错误均为零。

观察到的模型失败包括反复调用（`arith-0`、`mul_big-1020`、`div_big-4617`）、
给出正确 boxed 答案后仍继续生成（`div_big-7961`）、误读“Put together”且未使用计算器
（`add_or_sub_big-6890`），以及减法操作数顺序颠倒（`add_or_sub_big-8541`）。
最后一种情况下，计算器正确计算了模型提交的反向表达式。
本地加减法得分为 38/40，公开模型卡为 39/40；本地两组结果相同。
这是受控的本地重跑，并不声称在原作者软硬件配置下逐项复现全部公开得分。

诊断性的阶段累计耗时为：RISCuda 计算器 API 3.61 s，Qwenputer 芯片 token 阶段
804.33 s（2513123 个芯片 token）。这些计时器边界不同，截断的工作量也不同，
因此本报告不将二者商值作为独立计算器加速比。完整配对请求耗时是主要指标。
语言生成仍占 RISCuda 请求的主要成本。本实验未证明无 CPU 推理服务的加速、
批处理吞吐量或优于本地 CPU 工具。

另一次预热后的原生 C 计算器 Nsight 采样正确计算了
`12345678901234567890*98765432109876543210`。
记录到恰好**一次主机 kernel 启动和一个虚拟机 kernel**、**1870 条客户机指令**
及 **28 次原生十进制行服务**，没有与该 kernel 重叠的主机与设备间拷贝。
kernel 耗时为 **0.758 ms**；运行库请求计时为 8.67 ms，包含分配和传输，
计算器包装层计时为 12.28 ms。驱动和模块预热位于 `cudaProfilerApi` 采样区间之外。
此独立采样不是 LLM 请求耗时。全部 **69 项回归测试**通过，
wheel 和源码分发包资源检查也已通过。
